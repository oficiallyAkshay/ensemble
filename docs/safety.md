# Safety, permissions and privacy

The rule: Claude's microphone is never left recording because of Ensemble. The summary a reader needs is in the [README](../README.md).

## Safety design

| Check | What it does |
|---|---|
| Written before pressed | A record of "dictation started" is saved and flushed to disk before the microphone button is pressed. If the app crashes mid-recording, the next launch finds the record and stops it. |
| Dead-man check | While listening, the app must keep confirming it is alive roughly every second, or dictation is stopped. |
| Standing check | A timer verifies, even when nothing seems wrong, that Claude's microphone state matches what Ensemble believes. A start press still in flight keeps the record and restarts the off count, so the record clears only after the press has landed and the microphone has stayed off for 3 seconds; after a launch or wake the same holds, with no 3-second wait. |
| Fallback | If a stop cannot be confirmed within 3 seconds, or the microphone state cannot be read for 3 seconds while a record is open, Ensemble sounds an alarm and mutes the input device Claude is using (the same Claude processes, helpers included, that the recording check counts), recording the change so it can be undone later. A mute counts only once macOS accepts it and reads back silent; otherwise its record is dropped and the alarm still sounds. A muted device that was unplugged is unmuted when it comes back, once no stop is owed. |
| Only a definite "off" counts | The record is deleted, and the safety mute undone, only when macOS says plainly that Claude is not recording. An unreadable reading (the audio system restarting, say) counts as possibly recording, and a stop that finds no Claude session to press is not counted as a stop. |
| One dictation at a time | A new dictation is refused while an earlier one is still owed a confirmed stop, its alarm sounds or its safety mute is on, so that dictation's record, stop and mute are never replaced. |
| Switching off | Turning Ensemble off (or the automatic switch-off after a Claude update) stops any dictation and confirms the microphone is off before the record is cleared. A start press still in flight is waited for, up to 8 seconds; if it turns the microphone on, it is stopped at once. If it is still in flight after 8 seconds, the record stays, the dictation is stopped the moment the press lands, and the standing check clears the record once the microphone is off. |
| Quitting | Quitting stops dictation before the process exits. A start press already sent is waited for first, within the same 2 seconds, so a microphone it opens late is not read as off; if it is still in flight, nothing counts as off. A stop that cannot be confirmed with a definite "off" leaves the record and mutes the input, and the next launch puts it right. |
| Refusals | Dictation stops when you type or click, and a send is refused for 1.5 seconds after you type or click. Dictation stops and gestures are refused when more than one face is in view, when no face has been seen for 10 seconds, when the camera is covered, when another app starts using a microphone, when the input device changes, when the Mac sleeps, the screen locks or the screen saver starts, or when Claude quits. While the Mac sleeps, the display sleeps, the screen is locked or the screen saver runs, the camera is off and Ensemble moves no focus; it comes back on when you do. While you use the keyboard, mouse or trackpad, and for 2 seconds after (adjustable), focus and the highlight hold and nothing is resized; gestures still work, on the session your nose is on, and the dead-man check, the standing check and the alarm keep running. |
| A dictation Claude started | A dictation started with Claude's own button or shortcut is left alone until you act on it. A double pinch, a send or two Returns in that session take it over: the record is written before the stop is pressed, it is stopped and confirmed exactly like Ensemble's own, and a definite "off" is still the only thing that counts. A microphone that is on is never pressed to start, and a checkbox whose state is unclear is never pressed at all. |
| Return key | Only while a dictation runs in the session you look at (Ensemble's own, or one Claude started that the once-a-second session check saw recording), or for a moment after it (see below), does Ensemble watch the keyboard, and it only ever holds back a plain Return with Claude in front: the first one stops the dictation, a second one within the stop or 0.5 seconds asks for a send. Every other key, Shift-Return and any key with another app in front pass untouched, and no key is logged except as "Return". Holding Return down never sends: its repeats never count as a second press and are held back until the key is released. The watch goes off as soon as the dictation, that short window, any such hold and any send asked for with Return end, so a key typed before that send presses Send is seen and refuses it; if macOS pauses it, it is switched back on and any keys it may have missed count as typing, so no send follows (Ensemble switching the watch off itself is not a pause); if it cannot be created, Return keeps its normal behaviour. |
| Session widths | The peace sign, scissors and the chat-column fit move Claude's pane dividers with Claude's own keyboard control: Ensemble gives one divider keyboard focus through Accessibility, confirms Claude reports that divider as focused, and posts arrow, Shift-arrow, Home or End through the session event tap. Only with Claude in front, never while a dictation is starting, running or stopping, a send is in flight or the Return watch is on, and checked again before every key: if any of that changes, the divider loses the keyboard or you touch the keyboard or mouse, nothing more is pressed. No key is posted until the divider holds the keyboard, so a key never lands in a message box. The pointer never moves. From the moment a divider is asked to take the keyboard until the resize has ended, a key you type is held back (nothing about it is logged) and stops the resize; once the keyboard is back in the message box it is passed on, or dropped if a divider still holds the keyboard, so your keys never move a divider. Afterwards the keyboard goes back to the session's message box only if a divider of that row still holds it, so a box you clicked into keeps it; if Claude is not in front, that happens when Claude next comes to the front. Ensemble's own keys are never counted as your typing by the typed-or-clicked rules, the narrow send or the pause: a key whose time falls inside one of Ensemble's key windows counts only if the hardware also saw one. |
| Narrow send | Send needs Claude to be the app in front, a non-empty draft, dictation that ended in the last 30 seconds, and no keyboard or mouse use since. A dictation Claude started counts once Ensemble stops it, or once the session check sees it end (counted from when it was seen to end, up to a second after Claude stopped it). The draft is read from, and sent in, only the pane it was dictated into: same window, same session name, same place; if Claude changed its layout so that pane cannot be found, nothing is sent. Claude being in front is checked when the thumbs-up arrives and again right before Send is pressed; otherwise the island says "Not sent". A send asked for with Return twice goes through the same rules, with only those Returns not counted as typing, and only after the stop is confirmed. A dictation that sleep, a lock or the safety check interrupted at any point, even while it was starting or stopping, is never sendable. Once the stop is confirmed the send waits only until the draft has not changed for 0.3 seconds (at most 1.2 seconds), and the rules are checked again just before Send is pressed. A thumbs-up made while dictating stops the dictation as soon as it is recognised and lets the transcript settle while the hold runs; Send is pressed only once the hold has completed, and a hand that drops first leaves the text unsent. A draft you walked away from can never go out later from a stray gesture. |

Sending by gesture is not restricted by Claude's permission mode. Turn gesture send off in Settings to press Send yourself.

## Permissions

| Permission | Why |
|---|---|
| Camera | Reads your head direction and hand pose. Frames are analysed in memory and discarded. |
| Accessibility | Finds Claude's session panes and presses its dictation, Send and scroll controls. |
| Microphone, optional | Loudness only, for the live sound bars while Claude is listening. Never recorded. |
| Notifications, optional | Alerts and sound cues when a safety check refuses or stops something. |

Ensemble asks for the Microphone permission only for the live sound bars, and only when that setting is on, while Claude is listening. It reduces the input to one loudness number to animate the bars; the audio is never recorded, stored or sent. With the setting off, Ensemble never touches the microphone: Claude records, and Ensemble only watches which apps are recording. A Microphone permission request would appear the first time the bars are turned on.

## Privacy

- Video is analysed on your Mac. Frames are never written to disk and never sent anywhere.
- The face tracker is a web page served from inside the app through a custom address scheme, its model ships in the app, and every web address it could load is blocked.
- The only files written are settings, a small log rolled over at 1 MB with one backup, and the two safety records above.

The full table of what the app touches is in [SECURITY.md](../SECURITY.md).
