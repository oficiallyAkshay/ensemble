# Gotchas that have cost incidents

Ensemble has broken in specific, repeatable ways, and the fixes are not obvious from the code. Read the matching entry before you touch that area. Back to [AGENTS.md](../AGENTS.md) and the [contributing guide](../.github/CONTRIBUTING.md).

1. **Signing identity and TCC.** Camera and Accessibility grants are tied to the app's designated requirement. An ad-hoc signature is a new identity on every build, so grants silently stop working after each install. `scripts/bundle.sh` never signs ad hoc; it signs with one stable identity (`Ensemble Local Signing`, or `ENSEMBLE_SIGN_IDENTITY`). Changing the bundle id (`dev.ensemble.app`) or the signing identity drops every grant, and the owner must turn Accessibility on again by hand. A grant that shows on but does not work is cleared with `tccutil reset Accessibility dev.ensemble.app`; the menu panel's Reset button does exactly this for the user, and Restart Ensemble relaunches the app so a fresh grant applies. A copy that started without Accessibility relaunches itself once, within about a second of the grant showing (`GrantRelaunch`, checked by `HealthMonitor.checkPermissions`, never while the tour is open); a copy that started with the grant never does, which is what prevents a relaunch loop. The button stays as the fallback. The settings domain follows the bundle id. Never run `tccutil`, `defaults` or anything that touches the keychain or the installed app from an agent session. On a Mac that builds from source, macOS also asks on every rebuild whether `codesign` may use the "Ensemble Local Signing" key until the key's partition list allows it; `scripts/dev-install.sh` runs `security set-key-partition-list -S apple-tool:,apple:,codesign:` once (one login-password prompt in Terminal, and it carries on if cancelled). That prompt exists only for people who build from source; the downloaded app never uses the key.
2. **Claude desktop's controls exist only in its accessibility tree, and only after a flag.** Claude is an Electron app: set `AXManualAccessibility` to true on the app element, then retry discovery for about 3 seconds while Chromium builds the tree. A session pane is found by its dictation checkbox, labelled "Press and hold to record" (idle) or "Stop dictation" (recording); the session name is the header button whose description reads "<name>, rename session"; Send is a button labelled "Send". All are English labels of one Claude version. After a Claude update, check them first. Microphone state needs two sources, the checkbox value and CoreAudio's per-process capture flag, because either alone has lagged. The composer never reports `AXFocused` true, even with the caret in it (4 of 4 dictation starts logged "focus not confirmed"); whether keys land there is read from the app element's `AXFocusedUIElement` (the composer or something inside it). Claude's windows do not answer `AXWindowNumber` (attribute unsupported); `_AXUIElementGetWindow`, looked up at run time, gives the window server number, and session ids are built on it, so matching by frame alone let ids change while a move or resize had the two frames apart, or pick a hidden Claude window with the same frame. A full walk of the tree runs on Claude's own main thread, about 150 ms for a 12,000-node window, and its result can read empty for a moment while Claude re-renders: the 1 s refresh re-reads only the cached checkboxes, reads the pane frames only when Claude or the window server reports a change, walks again only when a window opens, closes or leaves the screen, a cached element is destroyed or stops answering, a pane changes inside a still window, or every 15 s (`SessionScan.plan`, `ClaudeWatcher`), keeps the list through one empty or cut-short walk while the cached checkboxes still answer, and stops any walk after 2 s (`SessionScan`). A session id is the window number plus the checkbox's order in it, so when Claude switches layout (one pane shown, then four) the same id can name another pane: a draft is read and sent only through `SessionMatch` (same window, same name, same place), never the plain id or overlap lookup. The divider between two side-by-side sessions is an `AXSplitter` labelled "Resize pane columns" (AXValue is that pair's split in whole percent, AXMinValue and AXMaxValue its limits, which follow Claude's minimum pane width of about 316 to 326 points; "Resize sidebar" is the sidebar's). Setting AXValue returns success and is ignored, and AXIncrement and AXDecrement do nothing. What works: set AXFocused on the splitter, confirm the app's AXFocusedUIElement is that splitter, then post keys through the session event tap: arrow 8 points, Shift-arrow 32, Home and End to the pair's limits (Page Up and Down do nothing). Measured 2026-10-15: keys 10 ms apart all land, the frames read back about 170 ms after a key, and the keyboard can take 0.7 to 1.6 s to move to another divider after a burst of keys (12 to 140 ms after a single key). The percent value is rounded, so judge a move by the splitter's frame, never by AXValue: whole-percent readings made landed keys look dropped. Zero sessions while another app is full screen is correct, since Claude is on another Space; the status then reads "Claude isn't on screen". Which accessibility notifications Claude posts (observed 2026-10-15, Claude 2.37337.1, four sessions, by a read-only observer for 40 minutes of normal use): a divider moving posts AXValueChanged on its `AXSplitter`, every time; the dictation checkbox posts AXValueChanged (0 to 1 and back) and AXTitleChanged when a dictation starts and stops, but after Claude switched layout (four panes, then one) the checkbox was a new element and a registration on the old one heard nothing, so the 1 s read of the cached checkbox stays the source of truth (a checkbox that stops answering makes the next read walk); coming to the front posts AXApplicationActivated, AXFocusedWindowChanged and AXMainWindowChanged; AXLayoutChanged and AXMoved or AXResized on web elements never arrived, so a pane's frame is never reported, only its window's and its divider's. Window moves and resizes, Space changes and a pane opening or closing did not happen while observed; the window server's list, compared on every 1 s check at no cost to Claude, catches the first three without any notification; a pane closing is caught by its checkbox no longer answering, and a pane opening by the divider changes it should post, or at the latest by the 15 s walk. Taken app-wide, AXValueChanged fires on every keystroke in a message box (127 in a few seconds of typing) and AXUIElementDestroyed and AXCreated fire about every 22 s for a hidden window Claude makes and drops, so Ensemble takes value changes and destruction only on the elements it cached, and a new window counts only once the window server lists it.
3. **Scrolling goes through the session event tap.** `CGEvent.postToPid` scroll events never reach Claude's web content. Post with `CGEvent.post(tap: .cgSessionEventTap)` with the pointer over the session, then `CGWarpMouseCursorPosition` puts the pointer back. A positive pixel delta scrolls the transcript down. Because the pointer is warped, any guard that counts mouse movement as the user's activity fires on Ensemble's own scrolling: guards count only key presses and clicks. The same holds for every event Ensemble posts itself: its own event tap shutting down arrives as `tapDisabledByUserInput` and once counted as the user typing (which refused the next send), and synthetic divider drags counted as clicks (divider keys would count as typing the same way). Anything Ensemble synthesizes must be excluded from the checks for "the user typed or clicked"; inside its own key windows those checks read hardware-only input state.
4. **Double-pinch timing comes from measured frames, never from intuition.** Check every change to the tap rules against the per-frame trace (hidden setting `detailedTrace`). Pinches within 0.7 s of a thumbs-up do not count (lowering a thumbs-up brushes thumb and index together). The window between the two pinches is 1.2 s; 0.6 s reset deliberate pairs. A hand in front of the face reads as a second face, so second-face detection is off.
5. **Overlay windows.** SwiftUI `.glassEffect` renders as a dark disc inside a transparent borderless panel; the nose dot is a separate small `NSPanel` holding `NSGlassEffectView`. SwiftUI insertions and removals animate only inside an animated change, so the view-level `.animation(value:)` on the shown session stays. An overlay panel waits 0.8 s before `orderOut` or every fade-out is cut off. `@Published` sinks fire before the stored value changes: read the value passed in, or dispatch to the next run-loop turn.
6. **Pausing other audio after macOS 15.4.** MediaRemote is closed to third-party apps. Use CoreAudio's `kAudioDevicePropertyDeviceIsRunningSomewhere` on the default output to see whether anything plays, skip headphones, read and set the volume through `kAudioHardwareServiceDeviceProperty_VirtualMainVolume`, and send a synthetic play/pause key. The key can reach the wrong app: check the audio stopped before the microphone opens and undo the press if not. Never lower the output volume (owner, 2026-10-15: Claude's and Ensemble's sounds must always play); the only way to silence other apps but not Claude is a CoreAudio process tap (`CATapDescription` excluding Claude's processes, `muteBehavior` muted), which needs the System Audio Recording permission (`NSAudioCaptureUsageDescription`, Privacy & Security, Screen & System Audio Recording) and, as Apple's sample uses it, an aggregate device with an I/O callback reading the tap while it runs. **Claude's dictation sounds need a user gesture.** Claude 2.37337's dictation recorder plays `enter_voice_mode.mp3` when recording starts and `exit_voice_mode.mp3` when it stops (`ion-dist/audio/voice/sfx/`), through a web audio context that Chromium's autoplay policy lets start only after a real click or key; an Accessibility press is not one, so after Ensemble's press Claude's sounds stay silent unless the owner clicked Claude's own button earlier. Ensemble plays the same files, read from the installed Claude at run time (never copied into this repository; Tink and Pop when they are missing), and skips its own when, within 0.15 s of the press, more Claude processes send audio out than just before it (a rise counts even if Claude was already playing; CoreAudio reports output per process, not its level, so a sound inside a process already playing is not seen). The "Kept, not sent" cue follows the same look as the stop it belongs to.
7. **Resources in the bundle.** SwiftPM's `Bundle.module` fails inside the signed app. Resolve resources with `EnsembleResources.bundle`.
8. **Workflows.** Every `uses:` is a full commit SHA with a version comment; resolve a SHA with `gh api repos/<owner>/<repo>/commits/<tag> --jq .sha`. Top-level `permissions: {}`, each job declares its own, every checkout sets `persist-credentials: false`, no `${{ }}` inside a `run:` step (pass it through `env:`), and a `run:` step that pipes into `tee` needs `shell: bash` so the pipe fails the step. There is no tag-triggered release workflow; releases run through `auto-release.yml` (Developer ID signing is not in use).
9. **Values the owner set by hand.** Do not revert them without asking: focus follows the nose after 0.075 s with a 28 pt margin; hold-to-send defaults to 0.75 s; the highlight is a blue outline only, never red and never filled; the menu bar icon is three small dots (hollow off, filled on); every motion uses one smooth spring curve and fades are never instant.
10. **History.** The repository history was rewritten once to the no-reply address before it went public. Never merge a branch created before that rewrite; it carries the old address.
11. **Headphone presses need Now Playing, not audio.** Measured on macOS 26.4: remote command handlers, `MPNowPlayingInfoCenter.nowPlayingInfo` and `playbackState = .playing` together are enough for the real play/pause and next-track keys to arrive; any one missing and nothing arrives, and a silent AVAudioEngine adds nothing, so none is used. `.paused` receives nothing, so the state stays `.playing` while claimed. Hold the claim only when no other app plays audio, or presses stop reaching the music. Ensemble's own synthetic play/pause key (the audio pause) can come back as a command: `HeadphoneRemote.lastSyntheticKeyAt` makes the filter drop it.
12. **Pointing corrects for head position (`HeadGeometry.swift`).** MediaPipe's matrix gives the head forward axis (third column) and position (m[12], m[13], m[14], cm) in one camera frame, so the correction treats the nose as a ray from that position along that axis and never assumes an axis flip; whether camera x is screen-right is read from the sign of the fitted map. Each screen's plane (sideways turn and distance) is fitted from its own calibration samples and the screen's physical size (`CGDisplayScreenSize`, with a 0.0233 cm per point fallback when macOS reports nothing sane). The affine map stays the only angle-to-point step: a reading away from the calibration spot is turned into the angles the same aim would have had at the spot, so the map is never extrapolated. Turning the head swings the reported position a few centimetres around the neck, so the position expected for each angle is fitted from the samples and only the difference counts; without that the calibrated spot itself would drift. Position readings that jump over 20 cm between frames or are implausible are ignored (accepted after about 0.7 s if they persist). Known limits: monitors are assumed upright (no backward tilt), the head forward axis is taken as the aim, and the centimetre scale is whatever MediaPipe assumes for the camera. A screen whose samples carry no position, or whose plane does not fit within 4 cm, points by angle alone. Turn it off with Settings, Display, "Correct for where I sit". Saved positions (`CalibrationSpot` in `SetupProfile.swift`) give a screen one map per position; the pointer picks, per screen, the position whose calibration head position is nearest (6 cm hysteresis), even with the correction off, and counts screens, not maps, for the one-screen rule (no clamp). Every position's copy of a screen must share one frame: storing a screen at a new frame drops the other positions' copies, or a moved screen would look valid through a stale copy. A run over only some screens anchors its first dot on a calibrated neighbour's centre (a turn away from it, not stillness), and a screen whose samples fall inside another valid screen's angle range from the same spot is refused: on 2026-10-15 a one-screen recalibration started from the main screen captured the main screen's angles for the left screen, was saved, and the nose never reached the left screen again. Calibration dots sit 4% in from each edge (`CalibrationTargets`), clear of the menu bar and notch.
13. **The development updater and macOS.** A launchd agent cannot read Desktop, Documents or Downloads: its bash exits 126 and nothing is logged, so `scripts/dev-install.sh` gives such a clone a build-only clone under Application Support. The macOS 27 SDK makes SwiftUI's `@State` a macro whose plugin ships with Xcode only, so with just the Command Line Tools `scripts/bundle.sh` builds against the macOS 26 SDK. Swift Testing's macro plugin is missing there too, so `swift test` cannot run on such a Mac and CI is the only test run: write tests so they compile first time. Seen to break CI (entry 21): a mutating call inside `#expect`, and `.nan` in a `CGRect` initializer (ambiguous; write `CGFloat.nan`). The size budget in `scripts/check-size.sh` failed CI whenever a feature added weight; raise it in the same change, with the reason in the script's comment. Development builds are stamped with the last tag plus `-dev.<short sha>` (build number = commit count) by `scripts/dev-update.sh`; releases are stamped by `scripts/ship-release.sh`, and a build that stamps nothing shows version 0.1.1.
14. **Two updaters on one Mac.** A development Mac running `scripts/dev-update.sh` must not also take Sparkle updates: a published release is signed on another Mac with another identity, so installing it drops the Accessibility grant (2026-10-15, 0.2.9 replaced a main build). Development builds are made without the update key, which keeps Sparkle off, and the updater replaces any installed copy that carries the key.
15. **The pointer dot must never hitch on a timer.** A once-a-second camera frame-rate report re-ran the pointer evaluation, which refit the pointer and reset the smoothing filter, so the dot stuttered every second. Nothing periodic may reset the filter. Also measured: hand pose on the shared camera queue dropped about one frame in ten (it has its own queue now), the face ran at 15 Hz (now every frame), the camera is locked to 30 fps (a common webcam tops out at 30 in every format), and the dot is drawn on every display refresh with a critically damped spring. The panel shows "camera 30 fps" and "dot 75 Hz" apart so the camera rate is not read as the dot rate.
16. **Status is live state, refusals are short-lived.** Text such as "your nose is not on a Claude session" went stale while the user was typing. Status always shows the current state; a refusal shows for about 6 seconds or until the condition that caused it resolves, whichever comes first.
17. **First run.** Permission prompts do not appear over the tour's Welcome page. The camera card has three states. The Accessibility Grant button opens System Settings. A copy run straight from the disk image sits on a translocated path, where open-at-login started a copy that relaunched every 5 seconds, so the app offers Move to Applications first. The microphone alarm always shows on the island, whatever the notification permission says.
18. **A delayed face tracker retry outlives the things that should cancel it.** A good head reading once reset the failure count but left the sleeping retry alive, so it restarted a tracker that had recovered; a stop or a camera start cancelled it only through the generation check. A failed tracker page that was not torn down could report a second failure, which counted against the backoff. While a retry waited the status read "Face tracking stopped", which sounded permanent. Now `TrackerRetry` numbers the waiting retry, `reset()` cancels it, a failure while one waits counts nothing, and `FaceTracker.fail` stops the page before reporting. Keep the cancel wherever the tracker is known to be healthy, and word any status shown during the wait as temporary.
19. **Removing a gesture slot, and the website demo.** Settings decoding ignores keys it does not know, so a gesture slot can be removed from the mapping and old saved settings still load. The website's demo port (`docs/live/logic.js`) mirrors the gesture logic in `EnsembleCore` by hand, so change both in the same pull request. `periphery` scans `EnsembleCore` only: unused code in the app target is not checked by CI, so look for leftovers there yourself after removing a feature.
20. **The local signing certificate expires.** Releases are signed with a self-signed certificate; once it expires, updates break, and a new certificate resets every user's grants (entry 1). `scripts/ship-release.sh` warns within 60 days of the date and refuses after it. The certificate is valid until 2036-10-11 (read 2026-10-19 from the exported certificate). Moving to Developer ID signing also resets Camera and Accessibility grants. The date and the plan (Developer ID signing before then) are in [RELEASING.md, "Signing certificate expiry"](RELEASING.md#signing-certificate-expiry).
21. **Two things that compile on a Mac with Xcode and fail only in CI.** The Command Line Tools cannot run Swift's macros (entry 13), so neither shows until the push. (a) Initialiser order: in an `init`, `self` cannot be used, not even inside a closure such as `x.hook = { [weak self] ... }`, until every stored property is assigned. `Coordinator` broke CI when the grant-relaunch hook was set before `focus`, `dot` and the other properties existed (b2d5cf7). Set hooks and callbacks after the last assignment in the `init`, or give the property a default. (b) A mutating call that is the whole expectation: `var rule = GrantRelaunch(...)` then `#expect(rule.shouldRelaunch(granted: true))` does not compile under `#expect`. Run the call on its own line, keep the result in a `let`, and expect on that (ad1f087, a4a7b29, 4a454a5). `scripts/check-test-traps.sh` refuses the second before a push (pre-commit's `check-test-traps` hook, installed with `pre-commit install --hook-type pre-push`; by hand, `scripts/check-test-traps.sh`). It flags only a call to a method declared `mutating func` under `Sources/` on a local `var` that is the entire argument of `#expect` or `#require`; setup calls and larger expectations are left alone, and `// trap-ok` on the line silences a name that is also a non-mutating method. It cannot see the initialiser-order trap, so read the `init` yourself.
22. **Link previews are cached by address, and Slack picks the layout.** The tags are in the head of `docs/index.html`; the image is `docs/assets/social-preview-2.png`, a copy of the repository's `Assets/social-preview.png` because the site publishes only `docs/`, and `docs/assets/oembed.json` describes the same image for Slack, which reads oEmbed before the tags. Slack caches a link's card for about 30 minutes ([Slack's robot page](https://api.slack.com/robots)), and a validator kept showing the old picture behind an address whose file had changed (2026-10-20). So a changed image gets a new file name, with the tags and `oembed.json` updated in the same pull request, and the check posts a link with a `?v=` value not used before. Keep the two image copies identical. Whether Slack draws a small right-hand thumbnail or a large image is Slack's choice: this page and the repository's GitHub link, both with `twitter:card` set to `summary_large_image`, drew the same small thumbnail, so more tags do not change it.
